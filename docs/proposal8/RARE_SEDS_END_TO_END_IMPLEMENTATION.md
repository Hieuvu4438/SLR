# RARE: End-to-End Implementation Specification for SEDS
## Residual Articulator-Aware Re-ranking for Fine-Grained Sign Language Retrieval

**Target repository:** `https://github.com/longtaojiang/SEDS`  
**Base paper:** *SEDS: Semantically Enhanced Dual-Stream Encoder for Sign Language Retrieval* (ACM MM 2024)  
**Purpose of this document:** this is an execution specification for an AI coding agent. The agent should be able to modify the SEDS codebase, reproduce the SEDS baseline, implement RARE, train it, evaluate it without leakage, and produce all ablations needed for a paper.

---

# 0. Executive decision

Do **not** replace SEDS.

Treat SEDS as a strong **stage-1 retriever** and add a **stage-2 residual reranker** that only processes SEDS's top-K ambiguous candidates.

The key design is:

\[
s_{\mathrm{final}}(q,v)
=
s_{\mathrm{SEDS}}(q,v)
+
\lambda \cdot \sigma_{\mathrm{cand}}(q) \cdot
\tanh\left(\Delta_\theta(q,v)\right),
\]

where:

- \(q\) is a text query;
- \(v\) is a sign video;
- \(s_{\mathrm{SEDS}}\) is the frozen first-stage score;
- \(\Delta_\theta\) is the RARE residual pair scorer;
- \(\sigma_{\mathrm{cand}}\) is the standard deviation of the stage-1 scores inside the top-K candidate set;
- \(\lambda\) is selected **only on validation data**;
- \(\lambda=0\) exactly recovers SEDS.

The reranker must be **query-conditioned** and must separately inspect:

1. RGB tokens;
2. SEDS fused pose-RGB tokens;
3. SEDS pose tokens;
4. left-hand tokens;
5. right-hand tokens;
6. body tokens.

The central training principle is:

> train on the errors made by SEDS, not on mostly random negatives.

# 1. Hard constraints

The agent MUST obey all constraints below.

## 1.1 No test-set tuning

Do not:

- tune \(\lambda\) on official test;
- choose epochs from official test;
- change K using official test;
- use official test captions/videos for hard-negative mining during training;
- select a checkpoint by official test R@1.

The official test split is run only after all hyperparameters and checkpoint-selection rules are frozen.

## 1.2 Stage-1 baseline must remain reproducible

Before adding RARE, reproduce SEDS with the official checkpoint and existing evaluation path.

Save:

```text
R@1
R@5
R@10
MedianR
MeanR
```

for both directions.

A RARE result is invalid if baseline reproduction is not within a small tolerance of the authors' provided checkpoint/result.

Recommended tolerance:

```text
absolute R@1 difference <= 0.2
```

If not reproduced, stop and fix the baseline first.

## 1.3 `lambda=0` must exactly recover SEDS ranking

Unit test:

```python
final_score = base_score + 0.0 * residual
```

must produce exactly the same ranking and metrics as the baseline.

For direction-specific top-K reranking, the order with `lambda=0` must also be identical to the SEDS order.

## 1.4 RARE must not alter the stage-1 candidate pool

During the main experiment:

- candidate retrieval is performed by frozen SEDS;
- RARE can only reorder candidates in the stage-1 top-K set;
- candidates outside top-K are not introduced by the reranker.

This isolates the contribution:

> SEDS = coarse retrieval, RARE = fine-grained discrimination.

## 1.5 Preserve the original evaluation protocol

SEDS uses a grouped multi-video-per-sentence protocol.

Do not silently replace it with a standard one-positive retrieval metric.

Implement a new clean metric module, but first prove that it matches the original SEDS metrics on the same similarity matrix.

- stage-1 SEDS trained on the same training partition used by RARE during development;
- final stage-1 SEDS retrained on the full train set after hyperparameters are frozen.

# 9. Articulator temporal aggregation

The raw GCN part features are frame-level:

```text
left_feat  [B, T, 512]
right_feat [B, T, 512]
body_feat  [B, T, 512]
```

SEDS already provides:

```text
clips_start [B, F]
slide_windows = 16
```

For each valid clip \(j\):

\[
a_j =
\frac{1}{W}
\sum_{t=s_j}^{s_j+W-1}
a_t
\]

for \(a \in \{\text{left,right,body}\}\).

Implement a vectorized helper.

Do NOT use nested Python loops in the final implementation.

Recommended implementation concept:

```python
def window_mean_tokens(
    frame_feat,     # [B,T,D]
    clips_start,    # [B,F]
    window_size,    # 16
):
    ...
    return tokens   # [B,F,D]
```

Implementation options:

1. pad then `unfold`;
2. create gather indices;
3. gather `[B,F,W,D]`;
4. average over W.

Recommended gather approach:

```python
B, T, D = frame_feat.shape
F = clips_start.shape[1]

offset = torch.arange(window_size, device=frame_feat.device)
idx = clips_start.clamp(min=0).unsqueeze(-1) + offset
idx = idx.clamp(max=T - 1)

expanded = frame_feat[:, None, :, :].expand(B, F, T, D)
gather_idx = idx[..., None].expand(B, F, window_size, D)

window = torch.gather(expanded, dim=2, index=gather_idx)
tokens = window.mean(dim=2)
```

For invalid `clips_start == -1`, zero the result.

Part mask:

```python
part_mask = clips_start >= 0
```

Do not add a synthetic CLS token at cache time.

RARE can learn global evidence through masked pooling.

For a text query \(t\), a candidate semantic/video group \(g\) can contain multiple videos.

Group score:

\[
S_{\mathrm{group}}(t,g)

\max_{v \in P_g}

The correct group is \(g=t\).

Rank all groups by `group_score`.

This should reproduce the original behavior where SEDS reduces a group with max over its video dimension.

# 16. Training hard negatives

RARE must use three negative pools.

## Pool A — rank-hard

The top SEDS false positives.

This is the most important pool.

## Pool B — visually confusable

Use frozen visual embeddings.

A simple robust visual descriptor:

```python
z_v = normalize(
    concat(
        mean_pool(fusion_tokens),
        mean_pool(pose_tokens),
        mean_pool(rgb_tokens),
    )
)
```

Visual similarity:

```python
sim_visual(v1, v2) = cosine(z_v1, z_v2)
```

For a positive video/group, retrieve visually nearest videos/groups whose text label differs.

## Pool C — random

Keep a small random-negative fraction for calibration.

Recommended training composition:

```text
60% rank-hard
30% visually-confusable
10% random
```

Do not spend the main batch on easy random negatives.

RARE is not a second full video encoder.

All expensive feature extraction is frozen/cached.

\[

```python
        e_m,
        q * e_m,
        torch.abs(q - e_m),
    ],
    dim=-1,
)
```

Dimension:

```text
4D = 2048
```

Shared score MLP:

```python
self.stream_score = nn.Sequential(
    nn.Linear(4 * D, D),
    nn.GELU(),
    nn.Dropout(0.1),
    nn.Linear(D, 1),
)
```

Then:

\[
d_m = MLP(q,e_m).
\]

Final residual:

\[
\Delta =
\sum_m w_m d_m.
\]

Optional interaction term:

```python
e_mix = sum(w_m * e_m)
```

and:

```python
delta_global = global_mlp([q, e_mix, q*e_mix, |q-e_mix|])
```

Final:

\[
\Delta
=
\Delta_{\mathrm{stream}}
+
0.5\Delta_{\mathrm{global}}.
\]

---

# 25. Zero-safe residual initialization

The final layer that outputs \(\Delta\) should be initialized to zero.

Example:

```python
nn.init.zeros_(self.final.weight)
nn.init.zeros_(self.final.bias)
```

If using stream score heads, initialize their last layers with a very small std or zero.

At initialization:

```text
delta ~= 0
```

so the reranker starts near SEDS.

---

# 26. Final score

Do not blindly add an unscaled neural score to a CLIP-scaled SEDS score.

For each candidate list:

```python
cand_std = base_scores.std(dim=-1, keepdim=True).clamp_min(1e-3)

residual = torch.tanh(delta)

score = base_score + lambda_train * cand_std * residual
```

Default training:

```text
lambda_train = 1.0
```

Validation sweep:

```text
lambda_eval ∈ {0.0, 0.1, 0.25, 0.5, 0.75, 1.0, 1.5, 2.0}
```

Selection rule must be predetermined.

Recommended primary selection metric:

\[
M =
\frac{R@1_{T2V} + R@1_{V2T}}{2}.
\]

Tie-breaker:

1. higher mean R@1;
2. higher mean R@5;
3. smaller lambda.

# 28. Multi-positive T2V loss

For T2V a text can have multiple positive videos.

Use multi-positive InfoNCE:

\[
L_{T2V}
=
-\log
\frac{
\sum_{p\in P}
\exp(s_p/\tau)
}{
\sum_{c\in C}
\exp(s_c/\tau)
}.
\]

Stable implementation:

```python
all_lse = torch.logsumexp(scores / tau, dim=-1)

pos_scores = scores.masked_fill(~positive_mask, -torch.inf)
pos_lse = torch.logsumexp(pos_scores / tau, dim=-1)

loss = -(pos_lse - all_lse).mean()
```

# 29. V2T loss

Each video has one positive text.

Use cross entropy over candidate texts.

```python
loss_v2t = F.cross_entropy(
    scores / tau,
    target_index,
)
```

=
\max(

m - s^+ + s^-
).
\]

# 31. Distillation/stability loss

The reranker should not make arbitrary changes.

Use a small residual penalty:

\[
L_{\Delta}
=
\frac{1}{N}
\sum
\Delta^2.
\]

Default:

```text
weight = 0.01
```

Optionally distill stage-1 candidate distribution:

\[
L_{KD}
=
KL(
softmax(S_{SEDS}/T)
\|
softmax(S_{final}/T)
).
\]

Recommended initial implementation:

```text
use residual L2 first
```

because it is simpler.

Add KL only as ablation if needed.

# 37. Inference

Inference must be two-stage.

## Stage 1

Frozen SEDS obtains candidate rankings.

## Stage 2

For each stage-1 top-K candidate pair:

```python
delta = rare(query_tokens, candidate_visual_tokens)
```

Final candidate score:

```python
score = base + lambda * std(base_topk) * tanh(delta)
```

Reorder only candidate list.

# 38. Strict top-K preserving mode

For the safest main experiment, do not allow RARE to change membership of the stage-1 top-K set.

It may only change order inside the set.

This gives two advantages:

1. stage-1 R@K remains unchanged by construction;
2. the scientific question becomes extremely clean:
   **can RARE promote the correct candidate from rank 2..K to rank 1?**

For final ranking:

```python
outside_candidates = original SEDS order after K
reranked_topk = sort(topk, final_candidate_score)

final_order = reranked_topk + outside_candidates
```

At `lambda=0`, the order is exactly the SEDS order.

This mode should be the primary reported setting.

# 39. T2V grouped inference

SEDS T2V compares semantic/video groups.

For each candidate group:

1. obtain its top `M_group` videos according to stage-1 pair score;
2. run RARE for those videos;
3. compute group score.

Default:

\[
S_{\mathrm{group}}
=
\max_v
S_{\mathrm{final}}(q,v).
\]

Ablation:

```text
max
logsumexp
```

Do not change from max in the main result unless validation clearly supports it, because max is closest to SEDS evaluation.

# 40. V2T inference

For each video:

1. take top-K candidate texts from SEDS;
2. run RARE for each text-video pair;
3. rerank those K texts;
4. append all remaining SEDS candidates unchanged.

# 47. Candidate batch vectorization

Never loop over K candidates in Python.

Suppose:

```text
B = 16
K = 20
```

Create pair batch:

```text
P = B*K = 320
```

Text query repeated:

```python
text_pair = text[:, None].expand(B, K, L, D)
text_pair = text_pair.reshape(B*K, L, D)
```

Candidate video features:

```python
video_pair = video_features.reshape(B*K, V, D)
```

Run one RARE forward over `B*K`.

Reshape:

```python
delta = delta.view(B, K)
```

This is critical for throughput.

# 65. Failure cases and actions

## Case A: vanilla reranker does not improve

Check in this order:

1. metric mapping;
2. text/video ID mapping;
3. whether positives are actually in top-K;
4. whether cached score equals baseline score;
5. whether residual magnitude is too small;
6. whether query and candidate pairs are mismatched;
7. whether candidate negatives are too easy;
8. whether candidate batch includes the positive.

Do not add more model layers before these checks.

## Case B: train improves but val does not

Reduce capacity:

```text
cross layers 2 -> 1
dropout 0.1 -> 0.2
```

Increase residual regularization.

Mix in more random negatives.

## Case C: RARE fixes errors but breaks many baseline-correct examples

Use:

- smaller lambda;
- safe-margin loss;
- stronger residual L2;
- top-K preserving ranking;
- smaller reranker.

## Case D: left/right/body hurts

Possible reasons:

- raw GCN part features are not text-aligned;
- scale mismatch;
- insufficient training examples.

Actions:

1. separate LayerNorm per part;
2. shared hand adapter;
3. reduce part residual adapter scale;
4. use part streams only as router context;
5. if still bad, keep them as ablation and retain RGB/Pose/Fusion reranker.

Do not force a component into the final model solely because it was proposed.

# 69. Residual adapter

```python
class ResidualAdapter(nn.Module):
    def __init__(self, dim=512, hidden=1024, dropout=0.1):
        super().__init__()
        self.norm = nn.LayerNorm(dim)
        self.net = nn.Sequential(
            nn.Linear(dim, hidden),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(hidden, dim),
        )
        self.scale = nn.Parameter(torch.tensor(0.1))

    def forward(self, x):
        return x + self.scale * self.net(self.norm(x))
```

Clamp or parameterize scale if it becomes unstable.

# 70. Pair scoring stability

Normalize pooled q/e vectors before pair feature construction:

```python
q = F.normalize(q, dim=-1)
e = F.normalize(e, dim=-1)
```

Do not normalize token features before MultiHeadAttention unless validation supports it; LayerNorm is sufficient there.

# 71. Candidate-list standard deviation

Function:

```python
def candidate_scale(base_scores):
    return (
        base_scores.float()
        .std(dim=-1, keepdim=True, unbiased=False)
        .clamp_min(1e-3)
    )
```

Use `unbiased=False` so K=1 edge cases do not produce NaN.
